# sdp-rtp Protocol Skill

Bounded, privacy-safe SDP structural evidence plus RTP version 2 / RTCP packet
evidence.

The package follows the RFC 8866 SDP grammar and a bounded RFC 3550 RTP/RTCP subset. It
publishes protocol structure and evidence classifications only. Missing mandatory RTP
flags remain `INCOMPLETE` and are never silently treated as false; RTP/RTCP version
values outside the two-bit 0-3 range are `INVALID`, and RTCP SR/RR report counts and
SDES/BYE source counts are validated type-specifically. It does not reconstruct
streams, compute local loss/jitter, perform MOS/QoS analysis, interpret Offer/Answer,
associate SIP dialogs, perform endpoint correlation (owned by `sdp-rtp-transport`), or produce IMS media/call verdicts.

## Usage

SDP:

```bash
python3 skills/protocol/sdp-rtp/scripts/parse-sdp.py \
  --input skills/protocol/sdp-rtp/examples/inputs/sdp-cases.jsonl \
  --output /tmp/sdp-analysis.json \
  --report /tmp/sdp-analysis.txt \
  --force
```

Structured RTP/RTCP:

```bash
python3 skills/protocol/sdp-rtp/scripts/extract-rtp-rtcp.py \
  --input skills/protocol/sdp-rtp/examples/inputs/rtp-rtcp-cases.jsonl \
  --input-format jsonl \
  --output /tmp/rtp-rtcp-events.json \
  --report /tmp/rtp-rtcp-report.txt \
  --force
```

Both extractors accept an optional owner-only local endpoint key. With the same key
and capture, they emit matching opaque endpoint references without publishing raw IP
addresses or ports:

```bash
python3 skills/protocol/sdp-rtp/scripts/parse-sdp.py \
  --input sdp-input.jsonl --output /tmp/sdp-analysis.json \
  --endpoint-key-file /secure/path/endpoint.key

python3 skills/protocol/sdp-rtp/scripts/extract-rtp-rtcp.py \
  --input rtp-rtcp-input.jsonl --input-format jsonl \
  --output /tmp/rtp-rtcp-events.json \
  --endpoint-key-file /secure/path/endpoint.key
```

For capture input, compound RTCP components are read from the local decoder PDML
hierarchy so SR and SDES components (and their report blocks) are preserved rather
than collapsed into one JSON component. For GTP-encapsulated RTP/RTCP, TShark JSON may
expose only the inner IP/UDP pair.
The extractor uses that pair only when exactly one IP and one UDP candidate exist,
an RTP/RTCP layer is present, and the pair is not the GTP-U port 2152. Anything else
remains `AMBIGUOUS`; outer and inner endpoints are never guessed or merged.

The key must be exactly 32 random bytes, must be owner-only on POSIX and is never
generated by these extractors. Without a key, endpoint references are absent and the
previous output shape is preserved. Authorized capture input uses an installed TShark
and an explicit caller-supplied decode mapping when needed:

```bash
python3 skills/protocol/sdp-rtp/scripts/extract-rtp-rtcp.py \
  --input /path/to/authorized-capture.pcapng \
  --input-format capture \
  --decode-as udp.port==5004,rtp \
  --output /tmp/rtp-rtcp-events.json \
  --force
```

TShark is never installed automatically. A capture without positive RTP/RTCP dissector
identification produces no fabricated events.

Input is JSONL with `source_reference`, `capture_file`, `capture_sha256`,
`frame_number`, `frame_reference`, `message_occurrence` and `sdp_body`. All records
must share one capture identity.

## Output

SDP output contains per-message evidence status, session structure, independent media
sections, recognised attributes, unknown attributes, redacted sensitive attributes,
reference integrity and bounded counts. RTP/RTCP output contains packet/component
references, RTP fixed-header fields, RTCP SR/RR report blocks, SDES item classifications,
BYE source/reason metadata, unsupported-family classifications and explicit
`not_confirmed` boundaries. Both text reports are human-readable summaries.

## Privacy

Raw SDP bodies, RTP/RTCP payloads, extension data, SDES text, APP data, feedback
payload, IP addresses, domain names, session names, usernames, session IDs, ICE
credentials, candidate data, fingerprints, crypto keys and arbitrary attribute values
are never published. Only bounded classifications, lengths, numeric protocol fields
and safe reviewed metadata values are exposed. SSRC values are capture-scoped protocol
observations, never subscriber identities. Optional endpoint references are keyed
HMAC-SHA-256 values that include the capture SHA-256; the key file is never published,
logged or committed, and raw endpoint tuples are never copied into output.

RTP packet identity may also be published as a capture-scoped, domain-separated
keyed HMAC over the complete decoded RTP packet bytes. Raw bytes and the key are
never published. An RTP header-tuple match alone is a header-signature observation,
not proof of byte identity, and byte identity never proves the physical cause of a
duplicate or retransmission.

## Limitations

RTP stream reconstruction, RTCP local statistics, local loss/jitter, MOS, media QoS,
SDP Offer/Answer pairing, SIP-to-SDP association, SDP-to-RTP endpoint correlation, ICE
verification and IMS media semantics are outside this Skill. RTCP report values are
remote-reported values. An `m=` line, RTP packet, SR/RR exchange or BYE does not
establish media delivery, two-way audio or call success.
