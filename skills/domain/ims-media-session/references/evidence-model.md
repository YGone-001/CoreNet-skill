# Evidence Model

## Composition chain

```text
IMS Session Attempt
  -> SIP Dialog Branch
  -> IMS Media Signaling Exchange
  -> SDP Offer/Answer message
  -> SDP media section
  -> SDP/RTP Transport Correlation record
  -> RTP UDP Stream / packet references
```

Each link uses an exact accepted reference. Filename similarity, frame
proximity, timestamp proximity, endpoint equality alone, Call-ID, tags, IP
address or port never creates IMS attempt or branch ownership.

## Input ownership

- IMS Session owns attempts, branches, Dialog references and release evidence.
- IMS Media Signaling owns Offer/Answer exchange association.
- SDP Analysis owns SDP message and media-section structure.
- SDP/RTP Transport Correlation owns capture-wide endpoint correspondence and
  UDP Stream references.
- This Domain owns only the IMS ownership association between those layers.

## Binding resolution

For every Correlation record:

1. Validate every SDP message and media-section binding.
2. Resolve each message against all exchanges that reference it as Offer or
   Answer.
3. Resolve candidate attempts and branches from those exchanges.
4. If all bindings are initial-offer messages of one attempt, publish one
   `ATTEMPT` / `ESTABLISHED` observation.
5. If exactly one established branch owns all non-attempt bindings, publish
   `BRANCH` / `ESTABLISHED`.
6. If multiple established branches or multiple attempts are involved, publish
   `AMBIGUOUS` / `AMBIGUOUS` with all candidate references.
7. If candidate exchanges exist but their branch identity or exchange
   establishment is insufficient, publish `UNBOUND` / `INSUFFICIENT_EVIDENCE`.
8. If no exchange references the SDP messages, publish `UNBOUND` /
   `NOT_ESTABLISHED`.

The original Correlation status and strength are copied unchanged. Binding status
is a separate IMS ownership classification.

## Indivisible Correlation record

A Correlation record may contain several SDP messages, media sections, streams
and candidate exchanges. It is never split into artificial per-branch records.
Its Domain observation reference is unique, and each Correlation reference occurs
exactly once in the primary inventory.

## Attempt-level shared offer

The initial INVITE Offer is attempt evidence. A shared offer used by forked
branches is published once as an attempt-level observation. Every branch record
references that same observation. The offer is not duplicated as branch-owned RTP
evidence.

## Historical Dialog lifecycle

A branch may be `CONFIRMED` or `TERMINATED`. Historical Offer/Answer evidence is
preserved for a terminated Dialog only when the accepted upstream artifacts
already established it. The Domain adds `release_outcome` as lifecycle context.

It never infers:

- RTP stopped after BYE;
- RTP stopped after a 200 OK to BYE;
- media resources were released;
- the media session was successfully terminated.

## Temporal boundary

`temporal_association_status = NOT_EVALUATED` and
`association_scope = CAPTURE_WIDE_ENDPOINT_CORRESPONDENCE_ONLY` are mandatory on
every transport observation.

The Domain does not claim that RTP packets:

- occurred during the INVITE-to-BYE interval;
- were caused by the corresponding INVITE;
- were generated by the same endpoint during the Dialog lifetime;
- were delivered to the intended subscriber;
- belonged to an active IMS media session.

No time window or timestamp-proximity matching is implemented.
